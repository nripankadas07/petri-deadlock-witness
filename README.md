# petri-deadlock-witness

Explore ordinary weighted place-transition nets and return a shortest unexpected deadlock firing sequence, explored-state count and explicit cutoff/unknown status.

For workflow designers testing small token-based synchronization models before implementation.

## Quickstart

Linux/Python3.10+; public source installation, no external service or runtime dependencies.

```sh
git clone https://github.com/nripankadas07/petri-deadlock-witness.git
cd petri-deadlock-witness
python -m venv .venv
. .venv/bin/activate
python -m pip install .
petri-deadlock-witness example.json
```

The command prints deterministic JSON. Invented acquire-only example reaches a deadlock after acquire; declaring that exact marking terminal makes it expected.

All input examples are invented. The tool reads one UTF-8 JSON file, at most1MiB, rejects duplicate keys/nonfinite numbers/unknown fields and never modifies the input. Exit0 means a completed nonfinding result; exit1 means a documented finding (infeasible deadline, unexpected deadlock, no route or failed inclusion). SQL reports all row outcomes with exit0. Exit2 means malformed/unsupported input with stderr and no partial report. Petri exit3 means incomplete exploration with no deadlock found; a found deadlock uses exit1 even if exploration is incomplete.

## Input and interpretation

Start with the exact structure in [example.json](example.json). [Expected JSON](example-output.json) is generated by the validated example.

Ordinary nonnegative integer weighted arcs only; no colored/timed/inhibitor/reset arcs, priorities, PNML import, fairness or liveness proof. Supplied token_limit is an exploration bound, not net capacity: an enabled over-bound transition causes UNKNOWN, never a false deadlock. state_limit bounds discovered states at1..10000; at most32 places/100 transitions/100 terminal markings. token_limit1..10^6; arc/initial values0..10^9, initial within bound. All terminal markings name every place. Only the first shortest deadlock is materialized; deadlock_count counts distinct unexpected deadlock markings among explored states. never_enabled_in_explored_states is an observation and not an unreachability proof if incomplete.

Identifiers are nonempty strings up to80 characters. Integer bounds exclude booleans. Required keys and types are validated. These are model diagnostics, not automatic changes to a live system. The report describes supplied data only.

```sh
python -m unittest -v

python -m pip wheel --no-deps . -w dist
python -m venv /tmp/petri-deadlock-witness-check
/tmp/petri-deadlock-witness-check/bin/python -m pip install --no-deps dist/*.whl
python verify_installed.py /tmp/petri-deadlock-witness-check/bin/python
```

Weighted arc consumption, shortest path, terminal exemption, bounded growth/state UNKNOWN, complete two-state cycle, initial deadlock and bad arc rejection.

Linux CI exercises Python3.10/3.12/3.14, wheel installation and the real installed console command from a temporary directory. [Validation details](VALIDATION.md) distinguish local and remote evidence. Windows/macOS and production data are untested.

## Why this small tool

A drawn workflow may consume a token without a restoring path; bounded exploration can be mistakenly presented as a complete safety result.

pg-lock-witness analyzes captured process wait edges and systemd-order-audit analyzes static dependency order. This explores changing token markings and possible synchronization deadlocks in a user-declared model.
